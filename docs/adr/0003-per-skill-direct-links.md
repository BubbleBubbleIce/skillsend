# ADR-0003: per-skill 直链，绝不主动迁移既有链接

日期：2026-08-28 · 状态：已接受

## 背景

用户当前环境存在手工维护的**链式链接**（`~/.claude/skills/X → ~/.agents/skills/X → ~/my_dev/skills/X`）以及真实目录混杂（`deveco-cli`）。链接策略有两种：per-skill 直链（每个 skill 一个 symlink，可独立开关）vs 整目录一条 symlink（简单但无法排除个别 skill、无法处理非 hub 内容）。

用户明确要求：**不要顺手破坏现有环境中的链接**。

## 决策

- 采用 **per-skill 直链**：`target/<skill> → hub/<skill>`，启用 = 建链，禁用 = 删链。
- 「已启用」判定 = 链接解析（任意跳数）最终指向 hub。既有的链式链接因此被正确识别并显示为已启用。
- 工具**绝不**主动迁移、重写、规范化既有链接。增删只发生在用户显式按下开关时，且只涉及该目标目录下的该一条链接。
- 只增删 symlink；对真实目录（无论是否同名冲突）永不创建、删除、覆盖，同名冲突只显示状态并告警。

## 后果

切换粒度到单个 skill × 单个 target，正是「切换小工具」的核心交互。既有链式链接会长期与直链共存（用户显式开关时会自然被替换为直链），工具对此不做清理，尊重环境现状。
